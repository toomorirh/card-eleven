## 6. 試合エンジン

### 6.1 基本式
- **有効値** `eff(p,k) = stat × pen × fatigue × situ`
  - `pen`: 細分ポジション適正 `posFit`(§3.4)。完全一致=1.0 / 同分類近接=0.92 / 同分類非近接=0.85 / 大分類違い=0.72
  - `fatigue = 1 − min(max, (inv×perAction + dload×perDef + 経過分×perMin)×staMul)`(`TUNING.fatigue`)。
    アクション主体: `inv`=関与回数(攻撃で起点/連携/シュートに絡む)、`dload`=守備負荷(被攻撃/被シュートをDFラインで分担→A案)。`staMul=1−(sta−1)/19×staReduce`(staが高いほど消耗が緩い)。iron持ちは常に1。活躍した選手ほど終盤に大きく低下しアクションが失敗しやすくなる。`gassedFeed` 超過で「疲れが見える」を一度告知。
  - **守備ラインの綻び**(B案) `lineDefMul(D)`: DFライン平均消耗が `lineFree`(不感帯)を超えた分だけ守備スコア(`resolveLink/Duel/Shot` の dSc/gSc)を `linePenalty` で減じる。疲れたDFラインは終盤に綻び失点しやすくなる(交代・守備的/持久型監督・スーパーサブの戦略価値)。rng非消費=判定順は不変。
  - `situ`: clutch(70分〜)、losing(ビハインド時)、heat(ボルテージ`volt>0.35`の熱い局面)を乗算(エモーショナルの"爆発"。相乗可)
- **ランダム** `rr() = 0.6 + random×0.8`(範囲0.6〜1.4)。各スコアに乗る。
- **支配率** `midPower`: 中盤の `tec×0.45 + spd×0.3 + sta×0.25` を選手ごとに加重(MF=1, 他=0.32)× `mid` × `poss`。tactic(atk1.05/def0.92)・style(short1.06/long0.94)補正。
  - 攻撃権は `mh/(mh+ma)` の確率でホーム。**モメンタム(下記)で `mh/ma` が動的に増減**。

#### 6.1.1 モメンタム&テリトリー(勢い/陣地) — 行動の支配率フィードバック
試合中の**行動**が支配率と起点位置に反映される戦術レイヤー(`volt`=演出の熱気とは別系統)。`TUNING.flow`。
- **`MC.mom`(-1..+1、+=自チーム優勢)**: デュエル勝ち/つなぎ成功/シュート/得点/奪取/連続攻撃で実行側に加算、被インターセプト/被タックル/クリア被弾/被奪取で相手側に加算。毎ティック中立へ減衰(`decay`)、`cap`でクランプ。`addFlow(T,base)`。
- **支配率反映**: `mh = midPower_H × max(0.2, 1+mom·possK)` / `ma = midPower_A × max(0.2, 1−mom·possK)`。良いプレーを続けた側が実際に支配率を上げ、押されると落ちる。`buildupSuccess` の edge にも波及。
- **テリトリー(起点の上下)**: 攻撃側の `territory(T)=momOf(T)·terr + (control−1)·terrCtrl` を、起点にボールが収まる位置(と起点トークン)の**攻撃軸オフセット**に加算。流れを掴めば高い位置から、押し下げられれば自陣深くから始まる。さらに `pickChannel(...,terrNorm(T))` で**起点の選ばれ方**も連動(押し込む=build/overlap寄り、押される=feed寄り)。
- **支配力 `control`(`flowControl`)**: `mid`スキル保有＋支配型(`type.poss`)の超過分を合算(1+)。(a)モメンタム獲得を増やし(`ctrlK`)、(b)相手のモメンタム奪取に耐性を与え(`resistK`=流れを渡さない)、(c)テリトリー基準ラインを押し上げる。→ **`mid`支配率スキル/司令塔型が「試合を落ち着かせて押し上げる」個性として明確に有効化**。
- **可視化**: 試合HUDに支配率バー(`#mbarFill`、`updateMomBar(share)`)。判定式(`resolveDuel/resolveShot`)には非干渉=支配率/起点レイヤーのみ。設定は「大きめ」(検証: flow ON/OFF比較でスコア不膨張、むしろ僅かに拮抗化)。

### 6.2 閾値 `TH`(攻撃側スコア > 守備側スコア × 閾値 で成功)
| キー | 値 | 用途 |
|---|---|---|
| duel | 1.1 | 中央1対1 |
| gk | 0.88 | シュート vs GK |
| side | 0.9 | サイド突破 |
| cross | 0.78 | クロスの競り合い |
| longPass | 0.95 | ロングフィード成立 |
| longRace | 1.08 | 裏抜けの駆けっこ |
| chain | 0.92 | ショートパス連携成立 |
| shortBonus | 1.12 | ショート成功後の勝負ボーナス |

### 6.3 攻撃スタイル別シーケンス
- 🎯 **center**: ペナルティエリア手前で得意勝負(spd/pow/tec を能力に応じ選択)→ tryShot
- 🏃 **side**: ウイングがタッチライン際を駆け上がる → 突破ならクロス → ターゲットがヘディング勝負 → tryShot(header)
- 🚀 **long**: 後方の起点 → 最前線へロブ → 受け手とDFが落下点で競走 → 裏抜けで GKと1対1 → tryShot
- 🔄 **short**: MF→MFのワンツー → 連携成立で中央勝負(shortBonusボーナス付き)
- **ロングカウンター**: 守備側が long スタイルだと22%で攻撃権を奪取。

### 6.4 シュート判定 `tryShot`
- `sBase` = 通常 `off×0.7+pow×0.3` / ヘディング `off×0.45+pow×0.55`
- `sSc = sBase × shoot × rr()` 、`gSc = GK.def × save × teamDef × rr()`
- `sSc > gSc × 0.88` で得点。**奇跡の手**保持GKは1試合1回これを無効化。

### 6.5 演出(縦ピッチ)
- フィールドは縦長(3:4)。自陣下・敵陣上。内部座標(攻撃軸x, 横y)を `toScreen(x,y)={sx:6+y*0.88, sy:97−x*0.94}` で画面に回転変換。
- ボール・選手が実際に移動(steps補間でカクカク=SFC感)。陣形ブロックがボールに追従して伸縮(最終ライン ball−34%、最前線 ball+16%)。コンパクトネス12%。積極性の高い選手2人が毎ティック飛び出す。
- カットイン: VS(SR/L同士または18%)、シュート!!、GOAL!!!(金レイ+画面シェイク)、SAVE!!、MIRACLE!!。
- チーム識別: 足元の発光リング(自軍=青H、敵=赤A)。ユニフォーム色はアトラスに焼き込み済み。

#### 6.5.1 カットインのレイアウト規約(縦位置の安定/帯内表示/アクション別)
2種の基本型 + アクション型に整理し、選手/語句サイズに依らず縦位置を固定する。
- **中央スタック型(`.cutin.csc`)**= GOAL/SAVE/MIRACLE/個人技/セットプレー/GAMESET。`.wc-fig` は固定高(118px)・下端揃え=スプライト/語句サイズに依らず選手のベースラインを固定(大きい図は上へはみ出す=ダイナミックさ)。ラベルは語句直下に流す(帯内)。**左右対称・中段**。
- **VS型(`.inner`/`.side`)**= マッチアップ(`maybeVs`)/PK(`pkCutin`)/KICK OFF。選手を `top:50%` 固定で左右対称配置、ラベルは帯上部ヘッダに固定(帯外に出さない)。
  - **マッチアップ勝敗表示(DF演出)**: `egoRun`/`through` で `resolveLink` を**先に1回だけ**評価し `won` を `maybeVs(...,won)`→`vsCutin` に渡す。対決後に勝者を発光+`✓`バッジ、敗者を暗転し、中央へ決着語(攻=`突破!`金 / 守=`STOP!`青)。判定順の変更で乱数列は変わるが分布(勝率)は不変。
- **アクション型(`.cutin.act`, スピード)**= ドリブル/パス/クロス。`afig`/`aword` を絶対配置しCSSキーフレームで動かす。
  - **ドリブル/カットイン突破**(`dribbleCutin`): 選手が左→右へゾーンを駆け抜けてワイプアウト、突破語句が追従(右流れ)。
  - **パス成功**(`passCutin`): 蹴り手+種別語が左に登場→左へワイプ→右から `パス成功!`→追って左に受け手が登場(左流れ)。`combination`=ワンツー / `through`=スルーパスに接続。
  - **クロス**(`crossCutin`): 上げ手が左でスピード感。
  - pass/cross は `skillShow()`(熱気連動)で頻度ゲート、ドリブル突破はエゴ成功時に表示。

#### 6.5.2 タイプ別フレーバー(演出のみ・勝敗ロジックには無関係)
同じアクションでも選手タイプで「言葉・系統色・タイプ名タグ」を出し分け、カットインの単調さを解消。
- データ駆動 `TYPE_FLAVOR`(`data.js`): タイプごとに `cat`(系統色 atk暖色/mid司令塔シアン/def守備青)と各アクション語句(`drive/cutin/pass/cross/atkWin/defWin/save`)。語句が無ければ汎用にフォールバック。`typeFlavor(c)`/`CAT_COL`/`CAT_ICON`。
- **ドリブル/カットイン**(`dribbleCutin(p,kind)`): 突破者タイプの語句(例 ドリブラー「切り裂く突破!」/ウインガー「サイドを置き去り!」)+系統色+帯上部にタイプ名タグ(`_ctag`)。
- **パス成功**(`passCutin`): 出し手タイプの語句(例 ゲームメーカー「司令塔のラストパス!」/アンカー「正確な楔のパス!」)。
- **クロス**(`crossCutin`): ウインガー「鋭いクロス!」/攻撃的SB「駆け上がってクロス!」。
- **マッチアップ勝敗**(`vsCutin`): 決着語/色を**勝者**のタイプで出し分け。攻撃勝ち=突破者(例 ドリブラー「抜き去った!」暖色)、守備勝ち=守備者(例 ストッパー「ブロック!」/カバー「カバーリング!」/アンカー「刈り取った!」青)。
- 色/タグはインラインstyleで付与(キーフレームの transform 上書きを避けるためタグのアニメは fade のみ)。**演出専用で eff/resolve には一切影響しない**。

#### 6.5.3 トレードマーク(必殺の型・演出のみ)
各タイプに**決め技(トレードマーク)**を1つ持たせ、個性を強く印象づける。`TYPE_FLAVOR[type].mark={at,w}`(`at`=発動局面 ego/through/cross/aerial/save/stop/goal、`w`=決め技名)。`trademark(p,at)`(`match-render`)が「その局面が選手の型の `mark.at` に合致」かつ「熱気 `volt≥TUNING.mark.volt`」かつ「`TUNING.mark.chance` で当選」の時 `markCutin`(タイプ系統色の決め技名+放射光の駆け抜け演出)を再生し `true` を返す。
- 攻撃系(ego/through/cross): 通常のアクション演出(dribble/pass/crossCutin)を**置換**する形で炸裂(二重演出を避ける)。守備/空中/得点(stop/aerial/goal): 稀な追加フラッシュ。
- 例: ドリブラー「🪄 エラシコ!」(ego) / レジスタ「🎼 一閃のレジスタ!」(through) / ゴールハンター「🦊 ゴールハンターの嗅覚!」(goal) / 守護神「🧤 鉄壁の反応!」(save)。
- **演出専用で eff/resolve・勝敗には一切影響しない**(発動確率も熱気ゲートのみ)。

### 6.6 ファウルとセットプレー(規律)
- **ファウル判定 `rollFoul(df,type,carrier)`**: 守備側がボール奪取に失敗した局面(`egoRun`/`through`)で低確率にファウル。**発生率に `ageFoul(df)` を乗算**=`AGE_PHASES` の `foul` レバー(若手1.12 → 成長期1.05 → 全盛期1.00 → ベテラン0.90 → 老雄0.84)で、**ベテランほど僅かにファウルしにくい**(`effAge` から `agePhase` を引く)。
- **カード/退場**: `bookFoul`→警告/退場を抽選(`TUNING.cards`)、`sendOff` で数的不利。詳細は [ゲームモード §7.13 規律](06-game-modes.md)。
- **負傷**: 各デュエル(`recMatch` 地点)で**勝敗によらず**攻守双方に `TUNING.injury.perDuel` で負傷判定(`rollDuelInjury`→`injurePlayer`)。負傷者は `eff` で**全能力×0.5**。通常戦はその試合限り、キャリアは3試合持続イベント化(治療で早期回復)。詳細は [ゲームモード §7.14 injury](06-game-modes.md)。
- **セットプレー**: `SETPIECES{fk,pk,ck}` レジストリへ `setPiece`/`setCorner` がディスパッチ(再帰防止 `_spActive`)。キッカーは編成ロール(§7.12)の設定選手を優先(`pickKicker`)。

#### 6.5.4 プレースタイルのUI表示
カード(`ui-roster`)・試合後スタッツ行にタイプ名を**系統アイコン+系統色**(`CAT_ICON`/`CAT_COL`)付きで表示し、各選手の個性を一目で読ませる。
