## 3. ステータスとレアリティ

### 3.1 レアリティと目標合計(1-20スケール)
| レア | 表記 | 6ステ合計(目標) | 1項目平均 | 生成基準 `RAR_TOTAL` |
|---|---|---|---|---|
| n  | ★      | 55  | 9.2  | 53 |
| r  | ★★     | 70  | 11.7 | 68 |
| sr | ★★★    | 90  | 15.0 | 88 |
| l  | LEGEND | 100 | 16.7 | 98 |

- `RAR_TOTAL` は丸め上振れを見込んだ内部目標(実測が目標値≒55/70/90/100に乗る)。
- **生成方式**: 6値に分散を持たせ、合計を `RAR_TOTAL` へ正規化し、1〜20にクランプ再配分。
  → 同レアでも個体差が出るが、合計は安定。
- `scaleTo(c, target)`: 既存6ステ合計を target へ比例スケール(1-20クランプ)。対戦相手生成と v8 移行で使用。

### 3.2 ポジション補正(生成後に加算)
| pos | 補正 |
|---|---|
| GK | def +3, off −3 |
| DF | def +2, pow +1, off −2 |
| MF | tec +2, sta +1 |
| FW | off +2, spd +1, def −2 |

### 3.3 ガチャ確率(プレイヤーパック・🪙100)
| 排出 | 確率 |
|---|---|
| sr | 5% |
| r  | 25% |
| n  | 70% |
- **LEGEND は通常ガチャから排出されない**(レジェンドパック専用)。
- **ハイクラスパック(🪙5000・コイン購入)**: 1枚入りで**シグネチャー or LEGEND 確定**(40%シグネチャー / 60%LEGEND、下位は出ない)。シグネチャー枠は `drawSignatureCard()` 共用のため**ごく稀(全体の約0.4%)に最上位エモーショナルへ到達**する。余りがちなコインの主要な使い道兼、固有選手の入手手段。高額のため開封前に確認ダイアログを挟む(`openPackById` の `cost>=1000` ガード)。

### 3.4 細分ポジションと2段階適正(pen)
大分類(`pos`: GK/DF/MF/FW)に加え、各カードは細分ポジション `sub` を1つ持つ。

| 大分類 | 細分pos(`SUBS_BY`) |
|---|---|
| FW | CF, ST, LWG, RWG |
| MF | OMF, CMF, DMF, LMF, RMF |
| DF | LSB, CB, RSB |
| GK | GK |

- 各細分posの大分類は `SUBGROUP[sub]` で導出(`subGroup(c.sub)===c.pos` が常に成立)。
- **大分類内の近接クラスタ `SUBNEAR`**(同クラスタ内=近接、別クラスタ=非近接):
  - FW: {CF, ST} / {LWG, RWG}
  - MF: {OMF, CMF, DMF} / {LMF, RMF}
  - DF: {LSB, RSB} / {CB}
  - GK: {GK}

**2段階適正 `posFit(cardSub, slotSub)` → pen 係数**(`POSFIT`):

| 段階 | 条件 | pen |
|---|---|---|
| 完全一致 | 細分posまで一致 | **1.00** (`exact`) |
| 同分類・近接 | 大分類一致 & 同クラスタ | **0.92** (`near`) |
| 同分類・非近接 | 大分類一致 & 別クラスタ | **0.85** (`far`) |
| 大分類違い | 大分類が異なる(例 MF→FW枠) | **0.72** (`group`) |

判定順は「①大分類の一致/不一致 → ②同分類内の細分(完全一致/近接/非近接)」の2段階。pen は試合エンジンの有効値計算(§6.1)に直接乗る。

- **フォーメーション(`FORMS`・全16種)**: 4-4-2 / 4-3-3 / 3-5-2 / 5-3-2 / 4-3-1-2 / 4-2-3-1 / 5-4-1 / 3-4-3 / 4-1-4-1 / 4-3-2-1 / 4-4-2ダイヤ / 4-2-2-2 / ゼロトップ / 4-3-3アシメ / 4-2-4 / 9.5番。各陣形に `KEYPOS`(要所)・`FORM_DESC`(説明)・`FORM_COUNTER`(守備陣形×攻撃スタイルの相性)を持つ。追加は `FORMS` に1エントリ+関連テーブル。QR共有はフォーメーションindexを**4bit**で格納(フォーマット版 `0xC6`・[データモデル](02-data-model.md)参照)。
- FORMS各枠は細分posで定義(`[sub, x, y]`)。大分類は `subGroup(sub)` で導出。座標は下記の標準ポジショングリッドに従う。
- **標準ポジショングリッド**(上=攻撃/下=自陣、x:左0〜右100、y:上0〜下100):
  - 最前列 CF / LWG / RWG ≈ y13–15、ST ≈ y28、OMF ≈ y38、MF段 LMF/CMF/RMF ≈ y49–51、DMF ≈ y60、DF段 LSB/CB/RSB ≈ y73–77、GK ≈ y90。
  - 中央列は CF→ST→OMF→(CMF)→DMF→CB→GK の順に縦に並べ、CF と ST のような同列の混同を防ぐ。
  - 同一細分が複数枠あるとき(CB×2 等)は x を左右に振って重なりを回避。
- 編成画面の可視化:
  - 各枠の**上部に適正ポジション名(slothead)**を常時表示(色は大分類)。
  - フィールドを **FW(赤)/MF(緑)/DF(青)/GK(金)** の帯ゾーンで色分け表示(`.zones`、y境界 0/33/69/86%)。
  - 配置カードの適正は枠色＋マークで表示: **✓**=完全一致(緑枠) / **金枠+本来の細分名**=同分類の細分違い / **赤枠+本来の細分名**=大分類違い。
- 画面レイアウト(スマホ操作配慮): OVR関連情報(**平均OVR/TOTAL=`teamOvr`** と **ケミストリー=`chemStatus`**)を**最上部**にまとめ、操作系(**フォーメーション選択 / 自動編成**ボタン)は**最下部**に配置。
- **自動編成**(旧「おまかせ編成」・`autoBtn`): 各枠を `[①大区分(FW/MF/DF/GK)一致 → ②同区分内はOVR(`total`)優先 → ③同OVRは `posFit`(exact>near>far)]` の順でソートして貪欲配置。**細分一致を基本としつつ、同じ大区分により高OVRの選手がいればそちら(細分違いでも)を優先**。同区分が尽きたら別区分へOVR順でフォールバック。
- ピッカー/交代候補のソートは `posFit` 降順 → 総合値降順。
- **ベンチ(交代枠)**(`BENCH_SIZE`=5・通常/育成 共通の構造): 先発XI(11)に加え**控えを事前に `S.bench`(通常)/`cr.bench`(育成)へ設定**。試合中の交代は**この事前ベンチからのみ**(`_beginMatch` が `MC.bench` を供給=通常は `S.bench`→`S.coll`、育成は `careerBenchCards`。`renderBench` は `MC.bench` から選ぶ)。従来の「`S.coll` 全体から交代」は廃止。交代回数は `MC.subs`=3。編成盤: 通常=`renderBenchSlots`/`openBenchPicker`(自動編成 `autoBtn` は残り上位でベンチも補充)、育成=編成盤に控え枠+`careerEditBenchPick`。
  - **育成の上限**: `careerCap`(素OVR上限)は**XI+ベンチ合計**を制約(`careerBaseTotal` にベンチ加算)。`careerTeam` は先発の実効上限を `cap−ベンチ素OVR` に下げてトリムし、ベンチ指定選手は先発の自動補完から除外(`careerBenchSet`)。超過は編成盤で赤・`startCareerMatch` がブロック。→「厚いベンチ or 強い先発」のトレードオフ。通常モードは上限なし(ベンチ自由)。
- `makeCard(pos, rar, base, sub)` の第1引数は大分類だが、細分pos(例 "LSB")を渡しても大分類へ正規化し細分として採用する(FORMS各枠の `sl[0]` をそのまま渡せる)。

### 3.5 国籍とケミストリー
- 各カードは国旗 `flag`(16ヶ国)を持つ。国名は `NATIONS[flag]` で導出(`natName`)。明示的な国名フィールドは持たず `flag` が正なので**マイグレーション不要**。
- **クラブ(所属選手・`scr-coll`・フッター👥)**: 所持選手の一覧。図鑑ではなく所属選手なので「クラブ」と呼ぶ。`renderColl` がフィルタ/ソート/まとめ売却を提供。
  - **レア度フィルタ**(`collFilter` チップ): 全/L/SR/R/N を枚数付きで表示・タップ絞り込み(`collRar`)。
  - **国籍フィルタ**(ドロップダウン `collsel`): 所持国籍を枚数付きで選択(`collNat`)。国籍が増えても省スペース(チップ羅列をやめドロップダウン化)。在庫が無くなった選択は「全ての国籍」へ自動リセット。
  - **ソート**(ドロップダウン): レア度順(既定)/OVR高い順/OVR低い順/国籍順(`collSort`・`_collSorted`)。
  - **まとめ売却**(`bulkSell`): **表示中(フィルタ後)の売却可能カードを一括売却**。`SELL_VALUE` 合計とレア度内訳を `confirm` で提示。**編成中(`inSquad`)・お気に入り(`S.favId`)・固有選手(`c.sig`)は除外**。レア度Nに絞ってから一括売却、等の運用を想定。
- カードタップで `🇪🇸 スペイン代表・名前(sub)|【スキル】説明` をトースト表示。
- **同国籍ケミストリー**: 編成された11人のうち**最多同国籍人数 `mx`** に応じてチーム全体を微強化。
  - 係数 `chem = 1 + min(0.06, max(0, mx−2)×0.012)`(3人=+1.2% / 5人=+3.6% / 7人以上=+6%上限)。
  - `recalcAuras` で算出し、`eff()`(全マッチアップ・シュート・GK守備の単一集約点)に乗算。
  - **両チームに対称適用**(相手も国籍がランダムに付くため公平)。編成画面に現在のケミストリー、試合開始時に発動実況を表示。

### 3.6 固有選手(シグネチャー)
実在モチーフのスペシャル選手。データ駆動の `SIGNATURES` 配列(`data.js`)で定義し、追加は1要素足すだけ。
- 各エントリ: `{id, name, flag, pos, sub, type, stats{6}, skill{name,desc,fx}}`。**不変条件: 6ステ合計=100(レジェンド級)/ いずれか1つ以上が20 / `subGroup(sub)===pos`**。
- `makeSignature(id)` でカード化。`rar:"l"`(レジェンド枠の演出を流用)+ `sig` 識別子を持ち、固定ステ・ユニークスキル・固有名・国籍を持つ。図鑑/カードでは **★★★★** 表示で通常LEGEND(ランダム生成)と区別。
- **モチーフ画像**: `src/assets/signatures/<id>.webp`(または png/jpg)に1ポーズを置くと、`build.py` が **SIGNATURESに登録済みのidと一致するものだけ** base64 データURI化して `window.SIG_IMG` を生成し、JSバンドル先頭に注入(単一HTML維持)。`spriteCanvas` が `c.sig` で分岐して描画(未配置時は★)。複数ポーズ入りの生ソース(`ce_py*`)は`<id>`にクロップするまで埋め込まれない。
  - **WebP圧縮(300体規模対応)**: クロップは `tools/crop_signature.py` が**高さ320px・WebP(q85)**で出力(`<id>.webp`)。PNG比 約92%削減(31体で 8MB→0.65MB / index.html 12.8MB→2.9MB)。300体でも約6MBで単一HTMLを維持できる。既存クロップも webp へ変換済み(生 `ce_py*.png` は再クロップ用に保持)。
- **入手**: 実績(トロフィー)報酬のみ。コイン購入・通常ガチャ・かけら合成は不可で、アスピレーショナルな到達目標として位置づける。詳細は §7.6。基本は**ランダム確定パック**(`S.sigPacks`)で入手し、特別な実績では**選択券**(`S.sigSelect`、好きな1名を指名獲得)が手に入る。
- **現在 全50名**(生ソース `ce_py1`〜`py50`)。メッシ/C.ロナウド/…(初期31名)に加え、ベリンガム/シェフチェンコ/ファン・ニステルローイ/フォルラン/ウーデゴール/サネッティ/ギャラス/ロナウジーニョ/上田綺世/シュヴァインシュタイガー 等を追加。**追加は `SIGNATURES` に1行＋`<id>.webp`** だけ。QRの sig ビット幅はフォーマット版で可変(v3以降=10bit=最大1023体)。エモーショナルは §3.6.1。

#### 3.6.1 エモーショナル(最上位レア・シークレット)
選手の**キャリアの“象徴的な瞬間(モーメント)”**を封じ込めた最上位カード。LEGEND/シグネチャーの上位。
- データ駆動の `EMOTIONALS` 配列(`data.js`)。エントリは `{id,name,flag,pos,sub,type,moment,momentSub,stats{6},skill}`。**不変条件はシグネチャーと同じ(合計100・いずれか20・subGroup一致)**=生ステは盛らず、特別さは**状況発動の効果と演出**で出す(パワークリープ回避)。
- `makeEmotional(id)` でカード化。`rar:"emo"` + `emo:true` + `sig`(画像共有) + `moment`。図鑑/券面では **EMOTIONAL** 表示・虹色イリディセント枠。**スキル枠でスキル名⇄モーメント(`moment`)をクロスフェード表示**(`.sk.emoalt`。専用帯は視認性が悪く廃止)。
- **特別能力(fx)**: `freekick`(FKキッカーに固定され直接FKを大幅強化=`pickShooter`が最優先選出。`SETPIECES.fk`が無回転FK専用シーケンスへ分岐し`spShot`をブレ球軌道+SUPER GOALで実行) / `drawFoul`(仕掛けた時に相手がファウルしやすく=`rollFoul`が攻撃側fxを乗算。看板FK/PKの登場を増やす) / `heat`(試合のボルテージが高い"熱い"局面でのみ爆発=`situ()`が `volt>0.35` で立ち上げ`volt=1`で`heat`倍) / `clutch`・`losing`(終盤・ビハインドで爆発、`situ()`で自動適用。heatと相乗し大舞台ほど手がつけられない)。生ステ据置のまま"状況爆発"で活躍する設計。
- **演出**: 試合中は専用 `emoMoment` カットイン(大判ヒーロー画像+虹色オーラ+題字、1試合1回 `_emoCut`)。ガチャは `revresult.emo` バナー。
- **画像**: `src/assets/emotionals/<id>.png`。`build.py` が signatures と同じ `window.SIG_IMG` に合流埋め込み(`_registered_sig_ids`/`_sig_block` が両ディレクトリを走査)。
- **入手**: シグネチャーパックから**シークレット1%**(未所持優先)。descには明記せず“出た時の衝撃”で見せる。
- 注意: QR共有(§カード61bit)は未対応で、エクスポート時は通常カードへ劣化(クラッシュはしない)。
- 現在: クリスティアーノ・ロナウド「7番の継承者」(マンU移籍直後のRWG・無回転FKの瞬間。moment="OLD TRAFFORD 2004")。

### 3.6.2 クラブ容量と図鑑のパフォーマンス
- **クラブ最大容量 `COLL_CAP`=500名**(`state.js`)。超過する入手はガード: パック開封(`drawPack`/`openPackById`は`coll.length + pack.n > 500`で不可+トースト)・選択券(`pickSignature`)・ワールド固有ドロップ(満員時スキップ)。コイン/在庫は消費しない。図鑑カウントに `所持 N/500` を表示。
- **図鑑/編成の負荷対策**(所持増で重くなる対策): ①グリッドの`.card`に `content-visibility:auto`(画面外カードの描画・無限アニメをブラウザが自動スキップ)。②図鑑は `COLL_PAGE`=60枚ずつ**ページネーション**(「もっと見る」で増分・フィルタ/ソート変更でリセット)。③`save()`は**デバウンス**(連続保存を1書込にまとめ、画面非表示/離脱時に`flushSave`で確実に永続化)。

### 3.6.3 パラレル(ガチャ限定の希少バリアント)
シグネチャーをガチャで引いた瞬間にごく稀に付与される**特別仕様の同一選手**。券面の色替え＋隠し能力で差別化する、収集の"当たりの中の当たり"。
- **データ**(`data.js` `PARALLELS`): `{id, name, rate, apply(c)}` のレジストリ。カードには `c.par`(id)を焼き込み、券面は CSS `.par-<id>` で分岐(枠・レーダー・"SIGNATURE"文字・ポジションバッジの色)。
- **抽選(`rollParallel`)**: **ガチャでシグネチャー当選時のみ**(`ui-gacha.js`)。各種を**独立レート**で判定し、複数当選時は**よりレア(低レート)を優先**(=最高レアが勝つ)。実績パック/選択券・限界突破では付与されない(ガチャ体験専用)。`applyParallel(c,id)` が `c.par` を記録し `apply(c)` を実行。
- **3種**:
  - 🔴 **DANGER ZONE**(`1/50`): 得意能力(値20)を**21へ**押し上げる(`apply` で 20→21)。上限を超える唯一の手段。券面=赤系。
  - 🟣 **TURBULENCE**(乱気流・`1/50`): **同じ大分類(FW/MF/DF)の全ポジションで枠適正=`POSFIT.exact`**(`posFitOf` 側で判定・§3.4)=どこに置いてもペナルティ無し。ステ/OVRは不変。券面=紫系、ポジションバッジ表記=**ANY**(バッジ色は素のポジション色を維持)。GKは実質効果なし。
  - ⚫ **OBSIDIAN**(黒曜石・`1/100`=最高レア): **スタミナ低下の影響を受けず常にフル性能**(`fatigue` が `c.par==="obsidian"` で 1 を返す=`match-core.js`。スタミナ自体は減るが試合性能に影響しない)。ステ/OVR不変。券面=国籍カラーを廃した漆黒背景＋銀ホロ。
- **拡張**: `PARALLELS` に1エントリ(＋`apply`＋CSS `.par-<id>`)追加で増やせる。ステを盛るタイプ(danger)と、盛らず特殊効果で差別化するタイプ(turbulence/obsidian)を混在させパワークリープを回避。

### 3.7 重複カードの活用(売却 / 限界突破)
図鑑でカードをタップすると詳細モーダル(`#cardModal`)が開き、重複の使い道を選べる(`ui-roster.js`)。
- **売却**(通常カード): `SELL_VALUE`(n20/r60/sr180/l400 コイン)で売却。**編成中の選手は不可**。固有選手は売却不可(限界突破に回す)。
- **限界突破(振り直し)**(固有選手): 同一シグネの**重複を1枚消費**し、**既存の限界突破ボーナスを一旦戻してから、20未満の能力1つに新たに +1〜3 を再抽選**。`c.lb`は**常に1能力のみ**({stat:inc})で、図鑑で強化能力を**色分け表示**(`.rlab b.lb`=シアン)。**加算累積ではない**ため OVR は「素+1〜3」に留まり(例: シグネ100→101〜103)、全選手がOVR120へ収束して没個性化する問題を回避。差別化は「どの能力に+が乗るか」の配分で行う。旧仕様の累積lbを持つカードは次回の振り直しで素+1〜3へ縮小。`lbDups(c)`(同sig・自分以外・編成外)が無いと不可。
- セーブ: 強化結果はカード(`c.<stat>`/`c.lb`)に焼き込まれ保存される(v9据え置き)。
