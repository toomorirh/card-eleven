## 11. テストと検証ハーネス(headless Node)

> 試合報酬は **`100+lv×40`(レベル依存)**。勝敗判定は固定値比較せず、必ず最終スコア(home/away)で判定すること(過去に固定140と誤判定したリグレッションあり)。

| スクリプト | 目的 |
|---|---|
| `integration.js` | モックDOMで全4スタイル+交代の試合完走を確認 |
| `hangtest.js` | ストレージ・画像が永久ハングする環境での起動・完走 |
| `scaletest.js` | レア別6ステ合計が目標値(55/70/90/100)に乗るか |
| `matchsim.js` | **中検証(Tier1)**: 試合インパクト・シム(下記) |
| 進行テスト | デッキを育てながらの想定勝率カーブ(スコア直読み) |
| ID整合チェック | 全 `getElementById` に対応する `id=` がHTMLにあるか |
| マイグレーション検証 | 旧v7(1-9)セーブのv8変換と既存進捗保持 |

**標準リリース手順**: 構文チェック(`node --check`)→ ID整合 → 統合テスト → ハング耐性 → (バランス変更時)進行テスト → 出力。

### 11.1 検証の三層(試合ロジック変更時)
試合エンジンを変えるときは、変更の規模に応じて検証強度を選ぶ。

- **Tier 0 軽**(毎回): `integration.js` / `hangtest.js` = クラッシュ・ハングなし。
- **Tier 1 中**(エンジン変更時): `matchsim.js`。シナリオ3(EVEN同戦力 / GAP戦力差 / TACT戦術切替)×陣形3(4-4-2 / 4-3-3 / 3-5-2)を **seed付きで N=300/セル**(計5400試合・約1.5s)回し、**試合フィンガープリント**(得点/シュート/決定率/勝率/関与の散り invCV/役職別関与シェア/採点 平均・SD)を **平均±95%CI** で算出。
  - 高速化: `transform` で `sleep` を即解決にし、`tickAsync` を直接駆動(描画はモックで no-op)。
  - 決定論的(seed=baseSeed+i 固定)。`--save` で `baseline_metrics.json` を採取、`--check` でベースライン比の各指標Δを「— 誤差内 / ▲▼ 有意(|Δ|>合成95%CI)」判定。
  - **挙動不変**の変更はペア・シード(同seedで結果一致)で確認、**意図的変更**は本シムの分布比較で影響を定量化。
  - 新エンジン固有指標(起点分布・連鎖長・リンク種別・マッチアップ整合)は改修時にテレメトリで追加し、設計目標に対して検証する。
- **Tier 2 重**(バランス確定時のみ): 全クラブ網羅・数千試合級の再キャリブレーション(普段はやらない)。
